# 2차원·1차원 MAC 성능 비교 로그

## 실행 정보

- 실행일: 2026-08-09
- 실행 주체: 사용자
- 실행 명령: `python3 main.py`
- 실행 모드: `data.json` 일괄 분석
- 실행 목적: 기존 2차원 MAC과 보너스 1차원 MAC의 실제 성능 기록 비교
- 개인정보 보호: 터미널 프롬프트의 계정명과 장치명은 기록하지 않음

## 실제 측정 결과

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | 속도비(2D/1D) | 시간 감소율 | 반복 횟수 |
|---|---:|---:|---:|---:|---:|
| 3×3 | 0.018674 | 0.012011 | 약 1.55배 | 약 35.7% | 1,000 |
| 5×5 | 0.039624 | 0.030537 | 약 1.30배 | 약 22.9% | 1,000 |
| 13×13 | 0.223035 | 0.191584 | 약 1.16배 | 약 14.1% | 1,000 |
| 25×25 | 0.765619 | 0.729598 | 약 1.05배 | 약 4.7% | 1,000 |

속도비는 `2차원 평균 시간 / 1차원 평균 시간`, 시간 감소율은 `(2차원 시간 - 1차원 시간) / 2차원 시간`으로 계산했다.

## 입력 출처

| 크기 | 입력 출처 |
|---|---|
| 3×3 | 코드 내부 기준 행렬 |
| 5×5 | `data.json size_5_1` |
| 13×13 | `data.json size_13_1` |
| 25×25 | `data.json size_25_1` |

## 측정 조건

- 2차원 측정 대상: `calculate_mac()` 1회
- 1차원 측정 대상: `calculate_mac_1d()` 1회
- 반복 횟수: 각 방식과 크기마다 1,000회
- 2차원 포함 시간: 행렬 검증과 이중 반복문 MAC
- 1차원 포함 시간: 1차원 입력 검증과 단일 반복문 MAC
- 공통 제외 시간: `data.json` 읽기와 콘솔 출력
- 1차원 추가 제외 시간: 2차원에서 1차원 리스트로 변환하는 시간

## 비교 분석

- 이번 실행에서는 네 크기 모두 1차원 MAC의 평균 시간이 더 짧았다.
- 3×3에서는 1차원 방식이 약 1.55배 빨랐고, 25×25에서는 약 1.05배 빨랐다.
- 두 방식 모두 N²개의 위치를 처리하므로 시간 복잡도는 O(N²)이다.
- 이번 측정에서는 행렬 크기가 커질수록 두 방식의 상대적인 시간 차이가 줄었다.
- 한 번의 실행만으로 차이가 줄어든 직접 원인을 확정할 수 없으며, 입력 검증·인덱싱 비용과 당시 시스템 상태가 함께 영향을 줄 수 있다.
- 실제 시간과 속도비는 Python 실행 환경과 시스템 상태에 따라 달라질 수 있다.

## 결론

- 필수 네 크기의 2차원·1차원 성능 기록 확보
- 모든 크기에서 같은 입력 출처와 1,000회 반복 확인
- 이번 환경에서는 1차원 방식이 약 1.05~1.55배 빠르게 측정됨
- 변환 비용을 제외한 MAC 호출 기준 비교임을 확인
