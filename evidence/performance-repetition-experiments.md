# 개별 호출·묶음 MAC 반복 횟수 추가 실험

## 실행 정보

- 실행일: 2026-08-13
- 실행 주체: 사용자
- 개별 측정 재현: `PERFORMANCE_REPETITIONS`를 10·100·1000으로 각각 설정한 뒤 `python3 main.py`의 모드 2 실행
- 묶음 측정 재현: `python3 benchmark_batch.py 10`, `100`, `1000`
- 공통 워밍업: 10회, 측정 제외
- 입력: 3×3 코드 내부 Cross/X 필터와 5×5·13×13·25×25 JSON Cross/X 필터
- 최종 코드 설정: `PERFORMANCE_REPETITIONS = 10`

## 실행 목적

- 개별 호출 표본 수 10·100·1000에 따른 평균과 변동 비교
- 타이머 한 구간 안에서 MAC을 10·100·1000회 실행하는 묶음 측정 비교
- 2차원과 1차원 MAC의 평균 시간 경향 확인
- 반복 횟수가 늘면 CV가 항상 감소하는지 확인

## 비교 요약

| 측정 방식 | 설정 | 8개 항목 평균 CV | 가장 큰 CV |
|---|---:|---:|---:|
| 개별 | 10 | 4.95% | 17.47% |
| 개별 | 100 | 2.97% | 8.70% |
| 개별 | 1,000 | 26.55% | 80.74% |
| 묶음 | 10 | 0.90% | 2.80% |
| 묶음 | 100 | 1.27% | 5.24% |
| 묶음 | 1,000 | 1.30% | 6.32% |

개별 100회는 이번 실행에서 개별 10회보다 평균 CV가 낮았다. 하지만 개별 1,000회에서는 2차원 5×5 `78.70%`, 1차원 3×3 `80.74%` 등 큰 변동이 발생했다. 반복 횟수를 늘리는 것만으로 운영체제 스케줄링이나 다른 프로세스 개입이 제거되지는 않는다.

묶음 측정은 대부분 개별 측정보다 낮은 CV를 보였다. 이는 여러 호출의 평균을 하나의 표본으로 사용해 짧은 지연과 타이머 비용이 분산된 결과로 해석할 수 있다. 다만 묶음 100회의 2차원 25×25 `5.24%`, 묶음 1,000회의 1차원 5×5 `6.32%`처럼 예외도 있었다.

## 2차원·1차원 평균 비교

모든 설정과 크기에서 이번 실행의 1차원 평균이 2차원 평균보다 낮았다. 개별 10회 기준 2차원 시간은 1차원보다 약 3×3 `1.84배`, 5×5 `1.74배`, 13×13 `1.55배`, 25×25 `1.11배`였다. 두 방식 모두 N²개 위치를 처리하므로 시간 복잡도는 O(N²)로 같다.

## 해석 제한

- 개별 표준편차는 MAC 호출 각각의 변동을 나타냄
- 묶음 표준편차는 묶음별 호출당 평균의 변동을 나타냄
- 두 CV는 표본 단위가 달라 같은 안정성 지표처럼 직접 비교할 수 없음
- 실행 순서와 시점의 CPU 상태·백그라운드 부하는 통제하지 못함
- 공식 제출 결과는 미션 최소 기준을 충족하는 개별 10회 결과만 사용함
