- 묶음 호출 수는 `--10` 옵션이 아닌 위치 인자 `10`, `100`, `1000`으로 받도록 유지
- 분리 전 결합형 로그의 24개 비교 중 묶음 평균과 묶음 CV가 각각 20개에서 더 낮게 측정된 결과 정리
- 낮은 묶음 CV가 개별 호출 안정성 향상을 뜻하지 않으며 측정 통계의 의미가 다름을 README와 증거에 명시
- 묶음 측정의 타이머 비용 분산 효과, 반복문 비용, 순서 영향과 시스템 개입 예외를 분석
- 공식 재현은 새 Python 프로세스에서 메뉴 2를 먼저 선택하고 같은 환경과 낮은 백그라운드 부하를 유지하도록 문서화
- 미션 학습 목표, 모드별 처리 흐름, 핵심 코드, 실제 FAIL 원인, 성능 통계와 보너스를 연결한 동료평가 학습 가이드 작성
- 최신 공식 성능값과 기존 조건의 과거 로그를 구분하고 동료평가 당일 재측정·설명 체크리스트 작성
- 미션 요구를 유지하면서 설명 부담을 줄일 다섯 가지 구현 단순화 방향과 단계별 결정표 작성
- 직접 3×3 입력을 생성 저장소와 분리하고 현재 실행에서만 사용하도록 변경
- 모드 1의 N×N 방식에서 JSON 탐색을 제거하고 생성 저장소 사용·즉시 생성 흐름으로 단순화
- JSON 데이터가 실행 중 생성 저장소에 섞이지 않도록 모드 2 저장 동작 제거
- 3×3 기본 필터와 JSON 필터를 먼저 사용하고 없는 생성 크기만 추가해 크기당 한 번 측정
- 별도 기준 행렬 생성 없이 기존 Cross/X 필터 두 개를 성능 입력으로 재사용
- 모드 1의 별도 `TIMING_REPETITIONS`를 제거하고 모드 1·2가 `PERFORMANCE_REPETITIONS`를 공유
- 모드 2의 전체 판정 요약을 성능 분석 앞으로 옮겨 MAC 성능표가 최종 출력이 되도록 정리
- 생성 저장소를 `{크기: Cross/X 필터}`로 단순화하고 사용자 패턴은 저장하지 않음
- CV는 상대 변동 참고 지표로 유지하고 README의 묶음 실험 설명은 증거 링크 중심으로 축약
- 필수 입력·JSON·크기 검증은 유지하고 중복 점수 변환과 긴 중첩 타입 힌트를 축소

## 확인된 입력과 환경

- 저장소 루트에 실제 `data.json` 존재
- 필터 크기: 5×5, 13×13, 25×25
- 패턴: 크기별 2개, 총 6개
- Python 확인 버전: 3.12.13
- 운영체제: macOS Sequoia 15.7.4
- CPU: 3.1GHz 6코어 Intel Core i5
- 메모리: 32GB 2667MHz DDR4

## 별도 실행을 생략한 항목

- `data.json` 파일 없음, UTF-8 인코딩 오류와 손상 JSON 처리 확인

## 현재 문제

- JSON 필터 오류를 케이스 반복 전에 전체 실패로 처리하던 문제를 수정했으며 사용자 실행 검증 전
- 모드 1 직접 입력과 공통 `MAC 성능` 표 검증 완료
- 네 필수 크기의 기존 필터 기반 성능표와 마지막 출력 순서 검증 완료
- 개별·묶음 10·100·1,000회 사용자 실행과 추가 실험 증거 확보 완료
- JSON에 없는 7×7 생성 필터의 추가·재사용과 크기순 성능 출력 확인 완료
- JSON과 같은 생성 크기의 중복 제거는 최신 코드로 미검증

## 다음 권장 작업 하나

**JSON 필터 크기 오류의 케이스 단위 처리 수동 검증**

사용자가 `data.json`의 한 필터 행 크기를 의도적으로 다르게 만든 뒤 메뉴 2를 실행한다. 해당 필터를 사용하는 케이스는 오류 사유와 함께 FAIL 처리되고 이후 크기의 케이스 분석이 계속되는지 확인한다.
