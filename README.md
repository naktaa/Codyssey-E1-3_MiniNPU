# Mini NPU Simulator

## 1. 프로젝트 소개 / 미션 목표

2차원 숫자 배열로 표현한 패턴과 Cross/X 필터의 MAC(Multiply-Accumulate) 점수를 계산하고, 두 점수를 비교해 패턴을 판정하는 Python 콘솔 애플리케이션입니다.

외부 연산 라이브러리 없이 반복문으로 MAC을 직접 구현했습니다. 3×3 사용자 입력과 `data.json` 일괄 분석을 지원하며, 3×3·5×5·13×13·25×25 행렬의 실제 측정 결과를 바탕으로 시간 복잡도 O(N²)를 분석합니다.

## 2. 실행 환경

| 항목 | 환경 |
|---|---|
| Python | 3.12.13 (요구 버전: 3.8 이상) |
| 운영체제 | macOS Sequoia 15.7.4 |
| CPU | 3.1GHz 6코어 Intel Core i5 |
| 메모리 | 32GB 2667MHz DDR4 |
| 외부 라이브러리 | 사용하지 않음 |

성능 수치는 위 환경에서 측정했으며 운영체제 상태와 실행 환경에 따라 달라질 수 있습니다.

## 4. 실행 방법

저장소 루트에 `data.json`을 둔 상태에서 다음 명령을 실행합니다.

```zsh
python3 main.py
```

```text
=== Mini NPU Simulator ===
1. 사용자 입력 모드
2. data.json 일괄 분석
3. N×N Cross/X 필터 생성
4. 종료
```

- 메뉴 1: 3×3 필터와 패턴을 직접 입력하거나 생성된 N×N 필터를 사용합니다.
- 메뉴 2: `data.json`의 모든 패턴을 판정하고 크기별 성능을 출력합니다.
- 메뉴 3: 3 이상의 홀수 N으로 Cross/X 필터를 생성합니다.

## 5. 필수 기능

### 5-1. 사용자 입력 모드

3×3 Cross 필터, X 필터와 패턴을 각각 한 행씩 공백으로 구분해 입력합니다. 입력이 완료되면 두 MAC 점수, 판정 결과와 3×3 MAC 성능을 출력합니다.

### 5-2. MAC 계산과 판정

패턴 `P`와 필터 `F`의 같은 위치를 곱해 모두 누적합니다.

```text
MAC(P, F) = Σ(i=0..N-1) Σ(j=0..N-1) P[i][j] × F[i][j]
```

NumPy 같은 외부 라이브러리 없이 이중 반복문으로 N²개 위치를 직접 계산합니다. 판정에는 부동소수점 오차를 고려해 epsilon `1e-9`를 적용합니다.

```text
|Cross 점수 - X 점수| < epsilon → UNDECIDED
Cross 점수 > X 점수             → Cross
Cross 점수 < X 점수             → X
```

### 5-3. JSON 일괄 분석

`data.json`의 `filters.size_N`에서 크기별 Cross/X 필터를 읽고, `patterns.size_{N}_{idx}`의 N과 같은 크기의 필터를 연결합니다. 각 케이스의 점수·판정·expected·PASS/FAIL을 출력한 뒤 전체 통과 및 실패 수를 요약합니다.

JSON에 사용된 라벨은 비교 전에 다음과 같이 표준화합니다.

| JSON 값 | 내부 라벨 |
|---|---|
| expected `+`, `cross` | `Cross` |
| expected `x` | `X` |
| filter key `cross` | `Cross` |
| filter key `x` | `X` |

### 5-4. 입력/데이터 오류 처리

- 사용자 입력의 열 개수나 숫자 형식이 잘못되면 오류가 발생한 행만 다시 입력받습니다.
- 빈 행렬, 비정사각형 행렬, 숫자가 아닌 값과 키에 표시된 크기 불일치를 검증합니다.
- 개별 패턴의 데이터 오류는 해당 케이스를 FAIL로 기록하고 다음 케이스를 계속 분석합니다.
- 파일 없음, 읽기 권한, UTF-8 디코딩과 JSON 문법 오류는 원인을 출력하고 해당 모드를 안전하게 종료합니다.

## 6. 필수 실행 결과

### 6-1. 사용자 입력 결과

3×3 필터 두 개와 패턴을 직접 입력한 결과입니다.

```text
[판정 결과]
Cross 점수: 2.000000
X 점수: 5.000000
판정: X
```

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² | 반복 횟수 |
|---:|---:|---:|---:|---:|---:|
| 3×3 | 0.001635 | 0.000323 | 19.76 | 9 | 10 |

### 6-2. JSON 결과

실제 `data.json`의 6개 패턴을 분석한 결과는 PASS 3건, FAIL 3건입니다.

| 케이스 | Cross | X | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.9 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.7 | X | X | PASS |
| `size_13_2` | 7.5 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.9 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

```text
전체 케이스: 6
통과: 3
실패: 3
판정 epsilon: 1e-09
```

### 6-3. FAIL 원인

`size_5_1`, `size_13_2`, `size_25_1`은 Cross와 X 점수가 정확히 같습니다. epsilon 정책에 따라 세 케이스의 실제 판정은 모두 `UNDECIDED`가 됩니다. 그러나 expected는 각각 X, Cross, X처럼 확정 라벨이므로 일치하지 않아 FAIL로 집계됐습니다.

따라서 이번 FAIL은 JSON 스키마, 라벨 정규화 또는 MAC 계산 오류가 아니라 입력 점수가 동점인 상황에서 정해진 비교 정책을 적용한 결과입니다. 실제 전체 출력은 [필수 실행 로그](evidence/simplified-final-run.md)에서 확인할 수 있습니다.

## 7. 필수 성능 분석

### 7-1. 측정 기준

- 대상: 2차원 `calculate_mac()` 한 번의 순수 곱셈·누적 구간
- 입력: 크기별 Cross/X 필터 쌍
- 반복: 워밍업 10회 제외 후 각 크기를 10회 독립 측정
- 타이머: `time.perf_counter_ns()`
- 제외: 파일 읽기, 콘솔 입출력, 행렬 검증과 워밍업
- 통계: 평균, 모집단 표준편차, `CV = 표준편차 ÷ 평균 × 100`

### 7-2. 실제 성능표

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² 연산 수 | 반복 횟수 |
|---:|---:|---:|---:|---:|---:|
| 3×3 | 0.001165 | 0.000203 | 17.47 | 9 | 10 |
| 5×5 | 0.001934 | 0.000056 | 2.88 | 25 | 10 |
| 13×13 | 0.008869 | 0.000048 | 0.55 | 169 | 10 |
| 25×25 | 0.029506 | 0.000118 | 0.40 | 625 | 10 |

### 7-3. O(N²) 분석

N×N 행렬은 행 N개와 각 행의 열 N개를 순회하므로 MAC 한 번의 곱셈·누적 횟수는 `N × N = N²`입니다. 따라서 시간 복잡도는 O(N²), 추가 누적 변수의 공간 복잡도는 O(1)입니다.

| 크기 변화 | N² 증가 비율 | 평균 시간 증가 비율 |
|---|---:|---:|
| 3×3 → 5×5 | 25 / 9 = 2.78배 | 0.001934 / 0.001165 = 1.66배 |
| 5×5 → 13×13 | 169 / 25 = 6.76배 | 0.008869 / 0.001934 = 4.59배 |
| 13×13 → 25×25 | 625 / 169 = 3.70배 | 0.029506 / 0.008869 = 3.33배 |

작은 행렬에서는 함수 호출과 타이머 같은 고정 비용의 비중이 커서 측정 시간 비율이 N² 비율과 정확히 일치하지 않습니다. 크기가 커질수록 고정 비용의 상대적 영향이 줄고, 13×13에서 25×25로 증가할 때 연산량 3.70배에 대해 시간이 3.33배 증가해 제곱 증가 경향이 더 뚜렷하게 나타났습니다. 측정값의 변동과 관계없이 코드가 정확히 N²개 위치를 방문한다는 점이 O(N²)의 직접적인 근거입니다.

## 8. 보너스

### 8-1. 1차원 MAC

2차원 행렬을 행 순서의 길이 N² 리스트로 미리 변환하고, 단일 반복문으로 같은 인덱스의 값을 곱해 누적합니다. 변환과 검증은 측정에서 제외했으며 2차원 방식과 같은 필터와 반복 횟수를 사용했습니다.

#### 8-1-1. 실제 성능표

필수 성능 분석과 동일한 입력·10회 반복 조건으로 측정한 1차원 MAC 결과입니다.

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² 연산 수 | 반복 횟수 |
|---:|---:|---:|---:|---:|---:|
| 3×3 | 0.000633 | 0.000086 | 13.59 | 9 | 10 |
| 5×5 | 0.001112 | 0.000035 | 3.12 | 25 | 10 |
| 13×13 | 0.005723 | 0.000045 | 0.79 | 169 | 10 |
| 25×25 | 0.026496 | 0.000208 | 0.79 | 625 | 10 |

#### 8-1-2. 2차원·1차원 비교

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | 1차원 감소율 |
|---:|---:|---:|---:|
| 3×3 | 0.001165 | 0.000633 | 45.67% |
| 5×5 | 0.001934 | 0.001112 | 42.50% |
| 13×13 | 0.008869 | 0.005723 | 35.47% |
| 25×25 | 0.029506 | 0.026496 | 10.20% |

감소율은 `(2차원 평균 - 1차원 평균) ÷ 2차원 평균 × 100`으로 계산했습니다. 이번 실행에서는 모든 크기에서 1차원 방식이 더 짧았지만 두 방식 모두 N²개 원소를 처리하므로 시간 복잡도는 O(N²)로 같습니다. 차이는 Python에서 중첩 인덱싱을 단일 인덱싱으로 단순화한 상수 비용에서 발생합니다.

### 8-2. N×N 필터 생성

메뉴 3에서 3 이상의 홀수 N을 입력하면 중앙 행·열이 1인 Cross 필터와 양쪽 대각선이 1인 X 필터를 생성합니다. 생성 결과는 `data.json`을 수정하지 않고 실행 중에만 보관합니다.

생성 필터는 모드 1의 패턴 판정과 모드 2의 성능 분석에서 재사용할 수 있습니다. 실제 7×7 필터 생성 후 모드 2에서 `3×3, 5×5, 7×7, 13×13, 25×25` 순서로 측정된 결과는 [생성 필터 재사용 로그](evidence/generated-filter-merge.md)에 기록했습니다.

## 9. 고찰

### 9-1. 대규모 행렬

N이 커지면 원소 수와 MAC 횟수가 N²으로 증가하므로 순차 반복문의 처리 시간이 빠르게 늘어납니다. 더 큰 행렬에서는 연속된 메모리 접근, 작은 블록 단위 처리, 여러 코어를 이용한 병렬 계산과 같이 계산량뿐 아니라 메모리 이동 비용을 줄이는 방법도 함께 고려해야 합니다.

### 9-2. CPU와 NPU

CPU는 다양한 분기와 범용 작업을 유연하게 처리하지만 이 구현처럼 MAC을 순차 반복하면 한 번에 처리하는 연산 수가 제한됩니다. NPU는 다수의 MAC 연산기를 병렬로 배치하고 데이터 재사용에 맞춘 메모리 구조를 사용해 행렬 연산의 처리량을 높입니다. 따라서 실제 AI 연산에서는 MAC 계산 자체뿐 아니라 데이터를 연산기로 공급하고 중간 결과를 저장하는 메모리 대역폭도 주요 병목이 됩니다.

## 10. 추가 실험

짧은 MAC 호출에서 타이머 비용과 반복 방식의 영향을 확인하기 위해 공식 10회 측정과 별도로 개별 호출 및 묶음 호출을 10·100·1,000회씩 비교했습니다. 묶음 방식은 여러 MAC 호출을 한 번에 측정한 뒤 호출당 평균으로 환산해 타이머 호출 비용을 분산합니다.

묶음 측정의 CV는 대체로 낮았지만, 이는 개별 호출 시간이 아니라 여러 호출의 평균값이 얼마나 변했는지를 나타냅니다. 따라서 공식 개별 측정의 CV와 같은 의미로 직접 비교할 수 없으며 미션의 필수 성능표에도 사용하지 않았습니다. 전체 수치와 해석은 [반복 횟수·묶음 추가 실험](evidence/performance-repetition-experiments.md)에 분리했습니다.
