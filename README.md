# Mini NPU Simulator

2차원 패턴과 Cross/X 필터의 MAC 점수를 반복문으로 계산하는 Python 콘솔 애플리케이션입니다. 3×3 사용자 입력과 `data.json` 일괄 분석을 지원합니다.

> 현재 상태: 필수 기능과 두 보너스 구현 완료. 저장 구조와 공식 성능 입력을 단순화한 뒤의 최종 실행 검증과 성능 재측정이 필요합니다.

## 실행 방법

### 환경

- Python 3.8 이상
- macOS, zsh 기준
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용

저장소 루트에 `data.json`을 두고 실행합니다.

```zsh
python3 main.py
```

메뉴는 다음과 같습니다.

1. 사용자 입력 모드
2. `data.json` 일괄 분석
3. N×N Cross/X 필터 생성
4. 종료

사용자 입력 모드의 하위 1번은 3×3 필터 두 개와 패턴을 모두 직접 입력합니다. 하위 2번은 실행 중 생성된 N×N 필터를 사용하며, 선택한 크기가 없으면 그 자리에서 Cross/X 필터를 생성한 뒤 패턴을 입력받습니다.

## 구현 요약

- 사용자 입력은 열 개수, 숫자 형식, NaN과 무한대를 확인하고 잘못된 행만 다시 입력받습니다.
- JSON은 메뉴 2 진입 시 한 번 읽고 같은 문서를 전체 케이스 판정에 재사용합니다.
- JSON의 패턴 키에서 N을 추출하고 같은 `size_N` 필터를 연결한 뒤 정사각형 구조와 크기를 검증합니다.
- expected `+`·`cross`·`x`와 필터 키 `cross`·`x`를 내부 라벨 `Cross`·`X`로 정규화합니다.
- `calculate_mac()`은 검증된 두 행렬의 같은 위치 값을 이중 반복문으로 곱하고 누적합니다.
- 두 점수 차이가 epsilon `1e-9` 미만이면 `UNDECIDED`, 아니면 더 높은 점수의 라벨로 판정합니다.
- 성능 분석은 이미 존재하는 Cross/X 필터 두 개를 그대로 사용합니다. 3×3은 코드 내부 기본 필터, 5×5·13×13·25×25는 JSON 필터, 그 밖의 크기는 실행 중 생성 필터를 사용하며 같은 크기는 한 번만 측정합니다.
- 각 크기는 10회 워밍업 후 순수 MAC 호출을 10회 독립 측정합니다. 워밍업, 입력 검증, 파일 읽기와 출력은 측정에서 제외합니다.
- 모드 1과 모드 2는 같은 성능 표 출력 함수를 사용합니다. 한글의 터미널 표시 폭을 고려해 열을 맞추며 평균 시간, 모집단 표준편차, CV, N² 연산 수와 반복 횟수를 출력합니다.

## 결과 리포트

### 사용자 입력 결과

3×3 필터 두 개와 패턴을 직접 입력한 기존 검증에서 다음 점수와 판정을 확인했습니다. 저장 구조 단순화 뒤에도 직접 입력은 다른 모드와 독립된 같은 흐름을 사용하며, 최종 실행은 다시 확인해야 합니다.

```text
Cross 점수: 3.000000
X 점수: 6.000000
판정: X
```

입력과 출력 원문은 [사용자 입력 실행 로그](evidence/manual-mode-success.md), 잘못된 행 재입력은 [입력 오류 로그](evidence/invalid-input.md)에서 확인할 수 있습니다.

### JSON 분석 결과

실제 `data.json`에는 5×5·13×13·25×25 필터와 총 6개 패턴이 있습니다. 기존 실행 결과는 PASS 3건, FAIL 3건입니다.

| 케이스 | Cross | X | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.9 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.7 | X | X | PASS |
| `size_13_2` | 7.5 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.9 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

세 실패는 모두 Cross와 X 점수가 같아 epsilon 정책에 따라 `UNDECIDED`가 된 경우입니다. expected는 확정 라벨인 Cross 또는 X이므로 실제 판정과 일치하지 않아 FAIL로 집계됐습니다. 이는 JSON 구조, 라벨 정규화나 MAC 계산 오류가 아니라 명시된 동점 정책에 따른 결과입니다. 상세 원문은 [JSON 판정 로그](evidence/json-analysis.md)에 있습니다.

### 성능 결과와 O(N²) 분석

성능 입력은 크기별 Cross/X 필터 쌍입니다. 패턴은 사용하지 않으며 2차원 방식은 두 필터를 그대로, 1차원 방식은 같은 필터를 측정 전에 펼쳐 사용합니다. JSON과 생성 저장소에 같은 크기가 있으면 JSON 필터를 우선해 한 번만 측정합니다.

저장 구조와 측정 입력을 단순화한 최신 코드의 실제 평균·표준편차·CV는 아직 재측정하지 않았습니다. 실행하지 않은 값을 작성하지 않으며, 이전 조건의 [10회 성능 로그](evidence/ten-run-performance.md)는 과거 기록으로 보존합니다.

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² | 반복 횟수 |
|---|---:|---:|---:|---:|---:|
| 3×3 | 재측정 필요 | 재측정 필요 | 재측정 필요 | 9 | 10 |
| 5×5 | 재측정 필요 | 재측정 필요 | 재측정 필요 | 25 | 10 |
| 13×13 | 재측정 필요 | 재측정 필요 | 재측정 필요 | 169 | 10 |
| 25×25 | 재측정 필요 | 재측정 필요 | 재측정 필요 | 625 | 10 |

표준편차는 10개 측정값이 평균에서 얼마나 흔들렸는지를 ms로 나타냅니다. CV는 `표준편차 ÷ 평균 × 100`으로 계산하며, 평균 크기가 다른 결과의 상대적인 변동을 참고하기 위해 표시합니다.

N×N MAC은 이중 반복문으로 모든 위치를 한 번씩 방문하므로 연산 위치 수는 N²이고 시간 복잡도는 O(N²)입니다. 예를 들어 13×13은 169개, 25×25는 625개 위치를 처리합니다. 실제 시간 비율은 타이머 비용과 운영체제 상태 때문에 N² 비율과 정확히 같지 않을 수 있지만, 행렬 크기가 커질수록 처리 위치 수가 제곱으로 증가하는 구조는 변하지 않습니다.

## 보너스

### 1차원 MAC

2차원 행렬을 측정 전에 행 순서의 1차원 리스트로 변환하고, 단일 반복문으로 같은 인덱스 값을 곱해 누적합니다. 변환과 검증은 측정에서 제외하며 공식 2차원 방식과 같은 입력과 반복 횟수를 사용합니다. 두 방식 모두 N²개 값을 처리하므로 시간 복잡도는 O(N²)입니다. 최신 비교값은 공식 재측정 후 반영합니다.

### N×N 필터 생성기

메뉴 3 또는 사용자 모드 하위 2번에서 3 이상의 홀수 N을 사용해 Cross/X 필터를 생성합니다. 생성 필터는 `data.json`에 쓰지 않고 실행 중 저장소에만 보관하며 같은 크기를 다시 생성하면 교체합니다.

사용자 모드 하위 2번에서 입력한 패턴은 해당 생성 필터와 판정할 때만 사용하고 저장소에는 남기지 않습니다. 성능 분석은 저장된 Cross/X 필터 두 개를 재사용하며 기존 JSON 크기와 같으면 중복 측정하지 않습니다.

### 추가 묶음 벤치마크

짧은 MAC에서 타이머 호출 비용의 영향을 확인하기 위해 `benchmark_batch.py`로 10·100·1,000회 묶음 실험을 수행했습니다. 묶음별 호출당 평균과 공식 개별 호출 측정은 통계적 의미가 다르므로 공식 결과에는 사용하지 않습니다. 상세 수치와 분석은 [묶음 벤치마크 로그](evidence/batch-benchmark.md)와 [분리 전 비교 로그](evidence/individual-batch-comparison.md)에 보존합니다.
