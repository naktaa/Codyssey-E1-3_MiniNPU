# Mini NPU Simulator

2차원 패턴과 Cross/X 필터의 MAC 점수를 반복문으로 계산하는 Python 콘솔 애플리케이션입니다. 3×3 사용자 입력과 `data.json` 일괄 분석을 지원합니다.

> 현재 상태: 필수 기능과 두 보너스를 구현하고 모드 1·2의 필수 10회 성능을 재검증했습니다. 생성 필터의 동일 크기 중복 제거와 새 크기 추가 흐름은 최종 확인이 필요합니다.

## 실행 방법

### 환경

- Python 3.8 이상
- macOS, zsh 기준
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용

저장소 루트에 `data.json`을 두고 실행합니다.

```zsh
python3 main.py
```

메뉴는 다음과 같습니다.

1. 사용자 입력 모드
2. `data.json` 일괄 분석
3. N×N Cross/X 필터 생성
4. 종료

사용자 입력 모드의 하위 1번은 3×3 필터 두 개와 패턴을 모두 직접 입력합니다. 하위 2번은 실행 중 생성된 N×N 필터를 사용하며, 선택한 크기가 없으면 그 자리에서 Cross/X 필터를 생성한 뒤 패턴을 입력받습니다.

## 구현 요약

- 사용자 입력은 열 개수, 숫자 형식, NaN과 무한대를 확인하고 잘못된 행만 다시 입력받습니다.
- JSON은 메뉴 2 진입 시 한 번 읽고 같은 문서를 전체 케이스 판정에 재사용합니다.
- JSON의 패턴 키에서 N을 추출하고 같은 `size_N` 필터를 연결한 뒤 정사각형 구조와 크기를 검증합니다.
- expected `+`·`cross`·`x`와 필터 키 `cross`·`x`를 내부 라벨 `Cross`·`X`로 정규화합니다.
- `calculate_mac()`은 검증된 두 행렬의 같은 위치 값을 이중 반복문으로 곱하고 누적합니다.
- 두 점수 차이가 epsilon `1e-9` 미만이면 `UNDECIDED`, 아니면 더 높은 점수의 라벨로 판정합니다.
- 성능 분석은 이미 존재하는 Cross/X 필터 두 개를 그대로 사용합니다. 3×3은 코드 내부 기본 필터, 5×5·13×13·25×25는 JSON 필터, 그 밖의 크기는 실행 중 생성 필터를 사용하며 같은 크기는 한 번만 측정합니다.
- 모드 1과 모드 2는 공통 `PERFORMANCE_REPETITIONS`를 사용합니다. 기본값은 10이며, 각 크기는 별도 워밍업 10회 후 순수 MAC 호출을 설정 횟수만큼 독립 측정합니다. 워밍업, 입력 검증, 파일 읽기와 출력은 측정에서 제외합니다.
- 모드 1과 모드 2는 같은 성능 표 출력 함수를 사용합니다. 한글의 터미널 표시 폭을 고려해 열을 맞추며 평균 시간, 모집단 표준편차, CV, N² 연산 수와 반복 횟수를 출력합니다.
- 모드 2는 케이스별 판정과 전체 요약을 먼저 출력하고, 2차원·1차원 MAC 성능표를 실행 결과의 마지막에 출력합니다.

## 결과 리포트

### 사용자 입력 결과

3×3 필터 두 개와 패턴을 직접 입력해 다음 점수와 판정을 확인했습니다.

```text
Cross 점수: 2.000000
X 점수: 5.000000
판정: X
```

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² | 반복 횟수 |
|---:|---:|---:|---:|---:|---:|
| 3×3 | 0.001635 | 0.000323 | 19.76 | 9 | 10 |

최신 입력과 출력은 [단순화 후 최종 실행 로그](evidence/simplified-final-run.md), 잘못된 행 재입력은 [입력 오류 로그](evidence/invalid-input.md)에서 확인할 수 있습니다.

### JSON 분석 결과

실제 `data.json`에는 5×5·13×13·25×25 필터와 총 6개 패턴이 있습니다. 최신 실행 결과는 PASS 3건, FAIL 3건입니다.

| 케이스 | Cross | X | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.9 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.7 | X | X | PASS |
| `size_13_2` | 7.5 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.9 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

세 실패는 모두 Cross와 X 점수가 같아 epsilon 정책에 따라 `UNDECIDED`가 된 경우입니다. expected는 확정 라벨인 Cross 또는 X이므로 실제 판정과 일치하지 않아 FAIL로 집계됐습니다. 이는 JSON 구조, 라벨 정규화나 MAC 계산 오류가 아니라 명시된 동점 정책에 따른 결과입니다. 최신 판정과 성능은 [단순화 후 최종 실행 로그](evidence/simplified-final-run.md)에 있습니다.

### 성능 결과와 O(N²) 분석

성능 입력은 크기별 Cross/X 필터 쌍입니다. 패턴은 사용하지 않으며 2차원 방식은 두 필터를 그대로, 1차원 방식은 같은 필터를 측정 전에 펼쳐 사용합니다. JSON과 생성 저장소에 같은 크기가 있으면 JSON 필터를 우선해 한 번만 측정합니다.

워밍업 10회를 제외하고 개별 MAC 호출 10회를 측정한 최신 결과입니다.

#### 2차원 MAC

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² | 반복 횟수 |
|---|---:|---:|---:|---:|---:|
| 3×3 | 0.001165 | 0.000203 | 17.47 | 9 | 10 |
| 5×5 | 0.001934 | 0.000056 | 2.88 | 25 | 10 |
| 13×13 | 0.008869 | 0.000048 | 0.55 | 169 | 10 |
| 25×25 | 0.029506 | 0.000118 | 0.40 | 625 | 10 |

#### 1차원 MAC

| 크기 | 평균 시간(ms) | 표준편차(ms) | CV(%) | N² | 반복 횟수 |
|---|---:|---:|---:|---:|---:|
| 3×3 | 0.000633 | 0.000086 | 13.59 | 9 | 10 |
| 5×5 | 0.001112 | 0.000035 | 3.12 | 25 | 10 |
| 13×13 | 0.005723 | 0.000045 | 0.79 | 169 | 10 |
| 25×25 | 0.026496 | 0.000208 | 0.79 | 625 | 10 |

표준편차는 10개 측정값이 평균에서 얼마나 흔들렸는지를 ms로 나타냅니다. CV는 `표준편차 ÷ 평균 × 100`으로 계산하며, 평균 크기가 다른 결과의 상대적인 변동을 참고하기 위해 표시합니다.

N×N MAC은 이중 반복문으로 모든 위치를 한 번씩 방문하므로 연산 위치 수는 N²이고 시간 복잡도는 O(N²)입니다. 예를 들어 13×13은 169개, 25×25는 625개 위치를 처리합니다. 실제 시간 비율은 타이머 비용과 운영체제 상태 때문에 N² 비율과 정확히 같지 않을 수 있지만, 행렬 크기가 커질수록 처리 위치 수가 제곱으로 증가하는 구조는 변하지 않습니다.

## 보너스

### 1차원 MAC

2차원 행렬을 측정 전에 행 순서의 1차원 리스트로 변환하고, 단일 반복문으로 같은 인덱스 값을 곱해 누적합니다. 변환과 검증은 측정에서 제외하며 2차원 방식과 같은 입력과 반복 횟수를 사용합니다. 두 방식 모두 O(N²)이며, 이번 10회 실행에서는 네 크기 모두 1차원 평균이 더 낮았습니다.

### N×N 필터 생성기

메뉴 3 또는 사용자 모드 하위 2번에서 3 이상의 홀수 N을 사용해 Cross/X 필터를 생성합니다. 생성 필터는 `data.json`에 쓰지 않고 실행 중 저장소에만 보관하며 같은 크기를 다시 생성하면 교체합니다.

사용자 모드 하위 2번에서 입력한 패턴은 해당 생성 필터와 판정할 때만 사용하고 저장소에는 남기지 않습니다. 성능 분석은 저장된 Cross/X 필터 두 개를 재사용하며 기존 JSON 크기와 같으면 중복 측정하지 않습니다.

### 추가 묶음 벤치마크

짧은 MAC에서 반복 횟수와 타이머 호출 비용의 영향을 확인하기 위해 개별 호출과 묶음 방식을 각각 10·100·1,000회로 실행했습니다. 개별 1,000회에서 큰 CV가 나온 항목이 있어 반복 횟수가 많다고 항상 안정적이지는 않았습니다. 묶음 표준편차는 묶음별 호출당 평균의 변동이므로 개별 호출 표준편차와 의미가 다릅니다. 상세 수치와 분석은 [반복 횟수 추가 실험](evidence/performance-repetition-experiments.md)에 분리했습니다.

- [x] 생성 필터 생성·교체와 모드 간 재사용
- [x] 단순화한 3×3 직접 입력과 공통 MAC 성능표
