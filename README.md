# Mini NPU Simulator

E1-3 미션용 Python 콘솔 애플리케이션 저장소입니다.

> 현재 상태: 단계 6 최종 검수와 문서 동기화 / 남은 오류 시나리오 검증 준비

## 실행 환경

- Python 3.8 이상
- 기본 검증 환경: macOS, zsh
- 외부 라이브러리 사용 금지
- 표준 라이브러리만 사용

## 실행 방법

저장소 루트에서 실행합니다.

```zsh
python3 main.py
```

현재 메뉴에는 다음 모드가 표시됩니다.

1. 사용자 입력(3×3): 정상 입력, X 판정과 오류 행 재입력 확인
2. `data.json` 일괄 분석: 6건 중 PASS 3건, FAIL 3건 확인
3. 프로그램 종료

`data.json`은 저장소 루트에 두는 것을 기본으로 합니다.

## 구현 요약

현재 구현된 핵심 로직은 다음과 같습니다.

- 숫자로 구성된 비어 있지 않은 n×n 행렬인지 검증합니다.
- 패턴과 필터의 크기가 같은지 확인합니다.
- 같은 위치의 값을 이중 반복문으로 곱하고 누적하여 MAC 점수를 구합니다.
- 정수와 실수를 `float` 점수로 계산합니다.
- 두 점수 차가 기본 epsilon `1e-9`보다 작으면 `UNDECIDED`로 판정합니다.
- 그 외에는 내부 표준 라벨 `Cross`, `X` 중 하나로 판정합니다.
- 무한대, NaN, bool과 숫자가 아닌 값은 명시적인 오류로 처리합니다.
- 필터 A(Cross), 필터 B(X)와 패턴을 각각 3×3 행렬로 입력받습니다.
- 열 개수나 숫자 형식이 잘못된 행만 다시 입력받습니다.
- 두 MAC 점수와 Cross/X/판정 불가 결과를 출력합니다.
- 패턴과 필터 A 사이의 `calculate_mac()` 한 번을 1,000회 반복 측정해 평균 시간을 출력합니다.
- 저장소 루트의 `data.json`을 UTF-8로 읽고 파일 없음·권한·UTF-8 디코딩·JSON 문법 오류를 구분합니다.
- `size_N_idx` 패턴 키에서 행렬 크기를 추출하고 대응하는 `size_N` 필터를 선택합니다.
- expected `+`와 필터 `cross`를 `Cross`, expected와 필터의 `x`를 `X`로 정규화합니다.
- 패턴과 필터의 정사각형 구조와 키에 표시된 크기가 일치하는지 확인합니다.
- 구조 오류가 있는 패턴은 오류 원인을 출력하고 다음 패턴 확인을 계속합니다.
- 각 패턴을 Cross/X 필터와 MAC 계산하고 epsilon 기준으로 판정합니다.
- 실제 판정과 expected를 비교해 케이스별 PASS/FAIL을 출력합니다.
- 데이터 또는 계산 오류도 케이스 FAIL로 기록하고 다음 케이스를 계속 처리합니다.
- 전체·통과·실패 수와 실패 케이스 사유를 출력합니다.
- 3×3·5×5·13×13·25×25의 `calculate_mac()` 한 번을 각각 1,000회 측정합니다.
- 크기별 평균 시간, N² 연산 수, 반복 횟수와 입력 출처를 출력합니다.
- 파일 읽기와 콘솔 출력을 제외한 측정 조건과 O(N²) 근거를 명시합니다.

핵심 정상 시나리오와 성능 분석은 사용자가 직접 실행해 확인했으며, 남은 오류 시나리오와 최종 실행 명령 재현은 별도로 검증합니다.

2. 통과 수: 3
3. 실패 수: 3
4. 실패 케이스: `size_5_1`, `size_13_2`, `size_25_1`
5. 데이터·스키마 문제 여부: 정상 케이스 6건, 구조 오류 0건
6. MAC 또는 판정 로직 문제 여부: 확인된 로직 오류 없음
7. 부동소수점 비교 문제 여부: epsilon 비교로 동점 처리
8. 라벨 정규화 영향: `x`와 `+`를 X/Cross로 통일해 비교 기준 일치
9. epsilon 값과 동점 처리 근거: `1e-9`, 점수 차이가 epsilon 미만이면 UNDECIDED
10. 3×3 평균 MAC 시간과 반복 횟수: 사용자 입력 `0.018066 ms`, 크기별 기준 측정 `0.018819 ms`, 각각 1,000회

12. 13×13 평균 MAC 시간과 반복 횟수: `0.222042 ms`, 1,000회
13. 25×25 평균 MAC 시간과 반복 횟수: `0.773164 ms`, 1,000회
14. N² 연산 횟수와 측정 시간 증가 관계: 9·25·169·625로 증가하며 평균 시간도 함께 증가
15. O(N²) 결론: 모든 위치를 이중 반복하므로 O(N²), 작은 크기에서는 고정 비용으로 비율 차이 발생

## 현재 확보된 JSON 로드 결과

사용자가 실제 `data.json` 로드 모드를 실행한 결과는 다음과 같습니다.

| 항목 | 실제 결과 |
|---|---:|
| 필터 크기 | 5, 13, 25 |
| 패턴 수 | 6 |
| expected X | 3건 |
| expected Cross | 3건 |
| 정상 케이스 | 6 |
| 구조 오류 케이스 | 0 |

모든 패턴 키에서 크기를 정상적으로 추출했고 같은 크기의 Cross/X 필터가 연결됐다. 상세 로그는 [JSON 로드와 정규화](evidence/json-load.md)에 기록했다. 이 데이터를 사용하는 MAC 점수, PASS/FAIL과 전체 통과·실패 집계도 실제 실행으로 확인했다.

## 현재 확보된 JSON 판정 결과

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.900000 | 0.900000 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.900000 | 0.100000 | Cross | Cross | PASS |
| `size_13_1` | 0.300000 | 14.700000 | X | X | PASS |
| `size_13_2` | 7.500000 | 7.500000 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.900000 | 4.900000 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.900000 | 0.100000 | Cross | Cross | PASS |

세 실패는 모두 Cross와 X 점수가 같아 `UNDECIDED`가 되었고 expected Cross/X와 일치하지 않아 발생했다. 이는 epsilon 동점 정책에 따른 의도한 FAIL이며 구조나 라벨 정규화 오류가 아니다. 상세 로그는 [JSON 일괄 판정](evidence/json-analysis.md)에 기록했다.

## 현재 확보된 크기별 성능 결과

| 크기 | 평균 시간(ms) | N² 연산 수 | 반복 횟수 | 입력 출처 |
|---|---:|---:|---:|---|
| 3×3 | 0.018819 | 9 | 1,000 | 코드 내부 기준 행렬 |
| 5×5 | 0.040140 | 25 | 1,000 | `data.json size_5_1` |
| 13×13 | 0.222042 | 169 | 1,000 | `data.json size_13_1` |
| 25×25 | 0.773164 | 625 | 1,000 | `data.json size_25_1` |

N×N MAC은 이중 반복문으로 모든 위치를 방문하므로 연산 위치 수는 N²이며 시간 복잡도는 O(N²)이다. 실제 측정에서도 크기와 N²가 증가할수록 평균 시간이 증가했다. 특히 13×13에서 25×25로 갈 때 N²는 약 3.70배, 평균 시간은 약 3.48배 증가했다.

작은 행렬에서는 함수 호출, 행렬 검증, Python 인터프리터와 타이머 관련 고정 비용의 비중이 크므로 측정 시간 비율이 N² 비율과 정확히 같지 않다. 상세 조건과 분석은 [크기별 MAC 성능](evidence/performance.md)에 기록했다.
