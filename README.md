# Mini NPU Simulator

E1-3 미션용 Python 콘솔 애플리케이션 저장소입니다.

> 현재 상태: 필수 미션과 보너스 1·2의 미션 원문 범위 구현 및 사용자 실행 확인 완료

## 실행 환경

- Python 3.8 이상
- 기본 검증 환경: macOS, zsh
- 외부 라이브러리 사용 금지
- 표준 라이브러리만 사용

## 실행 방법

저장소 루트에서 실행합니다.

```zsh
python3 main.py
```

현재 메뉴에는 다음 모드가 표시됩니다.

1. 사용자 입력: 기존 3×3 직접 입력 또는 저장·자동 생성 N×N 필터 사용
2. `data.json` 일괄 분석: 6건 중 PASS 3건, FAIL 3건 확인
3. N×N Cross/X 필터 생성
4. 프로그램 종료

`data.json`은 저장소 루트에 두는 것을 기본으로 합니다.

## 구현 요약

현재 구현된 핵심 로직은 다음과 같습니다.

- 숫자로 구성된 비어 있지 않은 n×n 행렬인지 검증합니다.
- 패턴과 필터의 크기가 같은지 확인합니다.
- 같은 위치의 값을 이중 반복문으로 곱하고 누적하여 MAC 점수를 구합니다.
- 정수와 실수를 `float` 점수로 계산합니다.
- 두 점수 차가 기본 epsilon `1e-9`보다 작으면 `UNDECIDED`로 판정합니다.
- 그 외에는 내부 표준 라벨 `Cross`, `X` 중 하나로 판정합니다.
- 무한대, NaN, bool과 숫자가 아닌 값은 명시적인 오류로 처리합니다.
- 필터 A(Cross), 필터 B(X)와 패턴을 각각 3×3 행렬로 입력받습니다.
- 열 개수나 숫자 형식이 잘못된 행만 다시 입력받습니다.
- 두 MAC 점수와 Cross/X/판정 불가 결과를 출력합니다.
- 패턴과 필터 A 사이의 `calculate_mac()` 한 번을 1,000회 반복 측정해 평균 시간을 출력합니다.
- 저장소 루트의 `data.json`을 UTF-8로 읽고 파일 없음·권한·UTF-8 디코딩·JSON 문법 오류를 구분합니다.
- `size_N_idx` 패턴 키에서 행렬 크기를 추출하고 대응하는 `size_N` 필터를 선택합니다.
- expected `+`와 필터 `cross`를 `Cross`, expected와 필터의 `x`를 `X`로 정규화합니다.
- 패턴과 필터의 정사각형 구조와 키에 표시된 크기가 일치하는지 확인합니다.
- 구조 오류가 있는 패턴은 오류 원인을 출력하고 다음 패턴 확인을 계속합니다.
- 각 패턴을 Cross/X 필터와 MAC 계산하고 epsilon 기준으로 판정합니다.
- 실제 판정과 expected를 비교해 케이스별 PASS/FAIL을 출력합니다.
- 데이터 또는 계산 오류도 케이스 FAIL로 기록하고 다음 케이스를 계속 처리합니다.
- 전체·통과·실패 수와 실패 케이스 사유를 출력합니다.
- 3×3·5×5·13×13·25×25의 `calculate_mac()` 한 번을 각각 1,000회 측정합니다.
- 크기별 평균 시간, N² 연산 수와 반복 횟수를 고정폭 표로 출력합니다.
- 파일 읽기와 콘솔 출력을 제외하고 MAC 함수 호출 구간을 측정합니다.
- 2차원 행렬을 행 순서대로 1차원 리스트로 변환합니다.
- 같은 입력을 단일 반복문의 1차원 MAC으로 계산합니다.
- 변환 시간을 제외하고 네 크기의 1차원 MAC 평균 시간을 기존 2차원 표와 같은 형식으로 출력합니다.
- 메뉴 3번에서 3 이상의 홀수 N을 입력받아 Cross/X 필터를 반복문으로 생성합니다.
- 생성 필터는 JSON에 쓰지 않고 프로그램 실행 중 크기별 딕셔너리에 보관합니다.
- 같은 크기를 다시 생성하면 실행 중 저장소의 기존 필터를 새 필터로 교체합니다.
- 모드 1에서 기존 3×3 직접 입력과 N×N 저장·자동 생성 필터 사용을 선택할 수 있습니다.
- 모드 1에서 사용한 패턴과 필터는 모드 2의 2차원·1차원 성능 분석 입력으로 재사용됩니다.
- 실행 중 생성한 추가 크기도 기존 필수 네 크기와 같은 반복 횟수로 성능 표에 포함합니다.

핵심 정상 시나리오, 성능 분석과 `python3 main.py` 최종 실행은 사용자가 직접 확인했다. JSON 파일·케이스 오류 경로는 구현을 확인했으며 별도 실행 증거는 사용자 결정으로 생성하지 않는다.

## 현재 확보된 크기별 성능 결과

| 크기 | 평균 시간(ms) | N² 연산 수 | 반복 횟수 |
|---|---:|---:|---:|
| 3×3 | 0.018682 | 9 | 1,000 |
| 5×5 | 0.039585 | 25 | 1,000 |
| 13×13 | 0.217348 | 169 | 1,000 |
| 25×25 | 0.758590 | 625 | 1,000 |

N×N MAC은 이중 반복문으로 모든 위치를 방문하므로 연산 위치 수는 N²이며 시간 복잡도는 O(N²)이다. 최신 측정에서도 크기와 N²가 증가할수록 평균 시간이 증가했다. 특히 13×13에서 25×25로 갈 때 N²는 약 3.70배, 평균 시간은 약 3.49배 증가했다.

작은 행렬에서는 함수 호출, 행렬 검증, Python 인터프리터와 타이머 관련 고정 비용의 비중이 크므로 측정 시간 비율이 N² 비율과 정확히 같지 않다. 최신 결과는 [생성기와 성능 출력 정리 확인](evidence/clean-performance-output.md), 이전 비교 기록은 [2차원·1차원 MAC 성능 비교](evidence/one-dimensional-performance.md)에 기록했다.

## 보너스 1차원 MAC 성능

2차원 패턴과 필터를 행 순서의 1차원 리스트로 미리 변환하고, 같은 위치의 값을 단일 반복문으로 곱해 누적하는 `calculate_mac_1d()`를 구현했다.

메뉴 2번의 기존 성능 표 아래에 다음 내용을 출력한다.

- 1차원 MAC 평균 시간
- N² 연산 수
- 각 크기의 실제 반복 횟수

1차원 변환은 측정 전에 한 번 수행하므로 성능 시간에 포함하지 않는다. 실행 중에는 기존 2차원 MAC을 추가로 계산하거나 속도비를 만들지 않는다. 사용자 실행 결과를 기록한 뒤 두 표를 비교한 결과는 다음과 같다.

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | 속도비(2D/1D) | 시간 감소율 |
|---|---:|---:|---:|---:|
| 3×3 | 0.018682 | 0.012007 | 약 1.56배 | 약 35.7% |
| 5×5 | 0.039585 | 0.030298 | 약 1.31배 | 약 23.5% |
| 13×13 | 0.217348 | 0.194398 | 약 1.12배 | 약 10.6% |
| 25×25 | 0.758590 | 0.733237 | 약 1.03배 | 약 3.3% |

이번 실행에서는 네 크기 모두 1차원 방식이 더 짧게 측정됐다. 두 방식 모두 N²개의 값을 처리하므로 시간 복잡도는 O(N²)이며, 1차원 방식은 행·열 이중 인덱싱 대신 하나의 인덱스를 사용한다. 이번 차이는 약 1.03~1.56배였으며 측정 환경에 따라 달라질 수 있다. 최신 값은 [생성기와 성능 출력 정리 확인](evidence/clean-performance-output.md)에 기록했다.

## 보너스 N×N 필터 생성기

메뉴 3번에서 3 이상의 홀수 N을 입력하면 Cross와 X 필터를 0과 1의 N×N 리스트로 생성한다. Cross는 가운데 한 행과 열을 사용하고 X는 두 대각선을 사용한다.

생성 결과는 `data.json`에 쓰지 않고 현재 프로그램 실행 중의 크기별 딕셔너리에만 보관한다. 같은 크기를 다시 생성하면 해당 크기의 필터를 교체한다. 모드 1의 N×N 방식에서 저장 필터를 선택할 수 있으며, 입력한 패턴과 필터는 이후 모드 2의 2차원·1차원 성능 측정에 재사용된다.

사용자 실행에서 3×3·5×5·7×7 Cross/X 필터 생성을 확인했고, 5×5를 다시 생성했을 때 교체 완료 메시지도 확인했다. 생성 3×3의 성능 분석 재사용과 간소화한 성능 표도 확인했다.

모드 1의 N×N 방식에서는 `data.json`에 없는 3×3 필터의 자동 생성, Cross `4.000000`, X `1.000000`, 판정 `Cross`, 단일 Cross MAC 1,000회 평균 `0.018306 ms`와 메인 메뉴 복귀를 확인했다. 같은 프로그램 실행에서 크기 3을 다시 선택했을 때 `3x3 저장 필터를 사용합니다.` 안내도 확인했다. 두 번째 실행의 점수와 시간은 전달받지 않았으므로 문서에 기록하지 않았다.

이로써 미션 원문의 패턴 생성, 모드 1 재활용과 성능 분석 재활용 흐름은 실행 확인을 마쳤다. 짝수·3 미만 크기 재입력과 생성 7×7의 성능 표 삽입 위치는 제출에 영향을 주지 않는 추가 항목으로 별도 실행하지 않았다. 상세 결과는 [모드 1 N×N 자동 생성·저장 필터 사용](evidence/manual-nxn-filter-flow.md), [생성기와 성능 출력 정리 확인](evidence/clean-performance-output.md), [생성 필터와 성능 재사용](evidence/generated-filter-performance.md)에 기록했다.
